# Adil's Working Preferences

How I want this project run. Applies to every session. If something here conflicts with a
default, this file wins.

## How you talk to me

- **Answer in points.** Bullets and short numbered lists, not paragraphs of prose.
- **Plain, easy words.** No jargon for its own sake. If a technical term is genuinely the
  right word, use it and define it in one line the first time.
- **Keep it short.** Say the thing, stop. No preamble, no recap of what I just said, no
  summary at the end of every message.
- Long output is allowed only when I ask for a document, a doc draft, or a full review.

## How you work

- **I run all git commands and CLI commands, not you.** Never commit, push, branch, or run
  shell commands on my behalf. Write the files, then *tell me the exact command to run* and
  I will run it. This is how I stay in control of my own repo and keep learning the tooling.
- Stay inside the current phase. Do not decide things that belong to a later phase — flag
  them as open and move on.
- Tell me when I am wrong, once, clearly. Then follow my decision and log it as an ADR.
- Explain the *why* before non-trivial code: the pattern, the alternative you rejected, and
  what it would cost to change later.
- Never invent facts about my product. Mark unknowns as `TODO(adil):`.

## How I learn

- Teach me the **name** of the concept, not just the fix.
- Every concept I meet goes in `learning-log.md`, one line.
- One comprehension question at the end of each slice.
