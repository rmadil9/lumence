## Phase 0 — Goal and users

**Status: done, 2026-10-24.**

### One persona, deliberately

**Decided: one persona.** Open signup is real ([ADR 0005](adr/0005-full-email-auth-plus-google-oauth.md))
and strangers are welcome, but nothing is designed for them.

- Everything in `02-spec.md` traces to Adil's own day, so a second persona would have to be
  invented — and an invented user quietly bends decisions toward someone who does not exist.
- Revisit only when a real second user turns up with a described need.

### Persona — Adil

Drawn from `01-problem.md`. Nothing here is invented.

| | |
|---|---|
| **Who** | Solo developer, building in public, ~10 hour days |
| **Machine** | Ubuntu, one laptop |
| **Uses today** | One LibreOffice document · a Google timer in a browser tab · a ChatGPT tab · X |
| **The pain** | Five kinds of output from one working day, living in five different places |
| **Stops using Lumence if** | It is worse to use than that, or does not save time against it |

### The three jobs

Chosen by Adil from a list of five. The two left out — refining writing with the LLM, and
reviewing where the day went — are **deliberate, occasional acts**. These three happen *inside*
the work, which is why they decide the design.

**1. Write the day's plan, each morning**
- Must be as fast as typing into a document that is already open.
- Today: alt-tab, type. **Zero aim.**

**2. Capture a thought mid-work, without breaking what he was doing**
- The highest-frequency job in the product.
- Interruption is the failure mode. If capturing a thought costs attention, the thought is lost
  and the tool is blamed.

**3. Commit to a focus block, and later check whether the commitment held**
- The only job that connects stated intention to measured reality
  ([ADR 0004](adr/0004-drop-per-todo-time-tracking.md) left it as the only one).
- The "later check" half is what makes the activity tracker the spine of the product rather than
  an accessory.

### The constraint all three share

**Everything Lumence replaces currently costs nothing to reach.** An open document takes zero
actions. Lumence starts behind on exactly the surfaces that matter most.

The measurable form of this: **how many actions between having the thought and typing?** Today it
is zero or one. Lumence must be one, at most — which makes "where is the cursor when the page
loads" a design decision rather than a detail.

### What Phase 0 rules out

- Any design that serves an imagined second user at Adil's expense.
- Any flow for jobs 1–3 that costs more actions than the tool it replaces.
- Anything that makes capturing a thought require aiming first.

## Phase 1 — Flows and screens

**Status: done, 2026-10-24.**

### Correcting the baseline

Phase 0 said everything Lumence replaces "costs nothing to reach". **That was wrong**, and Adil
corrected it. What today actually costs:

| Job | Today |
|---|---|
| Jot a thought | ~0 — the document is already open |
| Write the day's plan | ~0 — same document |
| Start a focus timer | Browser → find or open the Google tab → type → enter |
| Refine writing | Copy → switch tab → paste → read → copy → switch back → paste |
| See where the day went | **Impossible.** Nothing records it |

**Lumence starts behind on the notepad only, and ahead on everything else.** The fragmentation
*is* the cost — which is the premise of `01-problem.md`. The notepad is the single surface where
Lumence can lose.

### The three jobs as flows

**Job 1 — write the day's plan**
`open Lumence → todos panel → type` — typing *is* creating. No dialog, no save button.

**Job 2 — capture a thought mid-work**
`alt-tab → cursor already in the notepad → type` — two steps, one of which belongs to the
operating system. **This is the flow that must not grow.**

**Job 3 — commit to a focus block, then check it**
`start: timer page → type duration → enter`
`later: day view → pick the day → see the lock-in against where attention actually went`
The two halves are hours apart, which is why they live on different screens.

### Supporting flows

- **Refine writing:** `notepad → copy → chat screen → paste → read → copy → back → paste`.
  Still copy-paste by design (spec M, *Notes*); the win is that both ends are in one app.
- **Post on X:** `notepad → copy → button → X opens in a new tab`.
- **Set up tracking:** `register a device → token shown once → paste into the daemon's config`.
  A one-time flow that had never been designed. Iteration 2 needs it.
- **Auth:** `sign up → verification email → link → signed in`; `forgot password → email → link →
  new password`.

### Decisions — main screen

**The notepad owns the screen.** Three things side by side was rejected as clutter. The notepad
is full width by default, which also settles where the cursor goes: there is nowhere else for it
to be.

**Todos slide in from the left on a keyboard shortcut**, taking about a quarter of the width; the
notepad reflows. Not permanently on screen.
- **It remembers its last state.** Open stays open, closed stays closed.
- **It never force-opens** — not in the morning, not when today is empty. Rejected deliberately:
  a panel that appears on its own is a panel that appears when you did not want it.

**The shortcut must be a modifier combination.** The cursor lives in the notepad, so any bare key
is text. No single-letter shortcuts are possible anywhere on this screen.

**A shortcut-only panel is invisible to anyone who does not know it exists.** Accepted — there is
one persona and he will know. Screen 6 documents them.

### Decisions — timer

**Setting up and starting a lock-in lives on its own page**, not on main. This is parity with
today, where the Google timer is a separate tab.

**While a lock-in runs, a small countdown readout sits in the corner of the main screen.** Just
the number. A timer you cannot see is a timer you forget, and the readout costs almost no space.

**It beeps at 00:00:00**, as the Google timer does.
> **Scope change.** `02-spec.md` section L lists *"notifications when a session ends"* under
> **Out**. Adil put the beep back in on 2026-10-24: it is Google-timer parity and the timer was
> specified to behave exactly like the Google timer (ADR 0006). Small, and recorded rather than
> slid in.

### Decisions — shortcuts

**Fixed in v1. Not customisable.**
- A reference screen lists them. Nothing is stored per user.
- **Customisation was considered and deferred:** it needs a settings table, an editing screen and
  conflict detection, and `04-contracts.md` §1.8 states there is no settings table and nothing is
  configurable per user. [ADR 0006](adr/0006-lock-in-is-a-plain-countdown.md) avoided a settings
  area on purpose.
- **Additive later** — the table can arrive without disturbing anything decided here.
