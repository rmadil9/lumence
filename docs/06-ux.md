## Phase 0 — Goal and users

**Status: done, 2026-10-24.**

### One persona, deliberately

**Decided: one persona.** Open signup is real ([ADR 0005](adr/0005-full-email-auth-plus-google-oauth.md))
and strangers are welcome, but nothing is designed for them.

- Everything in `02-spec.md` traces to Adil's own day, so a second persona would have to be
  invented — and an invented user quietly bends decisions toward someone who does not exist.
- Revisit only when a real second user turns up with a described need.

### Persona — Adil

Drawn from `01-problem.md`. Nothing here is invented.

| | |
|---|---|
| **Who** | Solo developer, building in public, ~10 hour days |
| **Machine** | Ubuntu, one laptop |
| **Uses today** | One LibreOffice document · a Google timer in a browser tab · a ChatGPT tab · X |
| **The pain** | Five kinds of output from one working day, living in five different places |
| **Stops using Lumence if** | It is worse to use than that, or does not save time against it |

### The three jobs

Chosen by Adil from a list of five. The two left out — refining writing with the LLM, and
reviewing where the day went — are **deliberate, occasional acts**. These three happen *inside*
the work, which is why they decide the design.

**1. Write the day's plan, each morning**
- Must be as fast as typing into a document that is already open.
- Today: alt-tab, type. **Zero aim.**

**2. Capture a thought mid-work, without breaking what he was doing**
- The highest-frequency job in the product.
- Interruption is the failure mode. If capturing a thought costs attention, the thought is lost
  and the tool is blamed.

**3. Commit to a focus block, and later check whether the commitment held**
- The only job that connects stated intention to measured reality
  ([ADR 0004](adr/0004-drop-per-todo-time-tracking.md) left it as the only one).
- The "later check" half is what makes the activity tracker the spine of the product rather than
  an accessory.

### The constraint all three share

**Everything Lumence replaces currently costs nothing to reach.** An open document takes zero
actions. Lumence starts behind on exactly the surfaces that matter most.

The measurable form of this: **how many actions between having the thought and typing?** Today it
is zero or one. Lumence must be one, at most — which makes "where is the cursor when the page
loads" a design decision rather than a detail.

### What Phase 0 rules out

- Any design that serves an imagined second user at Adil's expense.
- Any flow for jobs 1–3 that costs more actions than the tool it replaces.
- Anything that makes capturing a thought require aiming first.

## Phase 1 — Flows and screens

**Status: done, 2026-10-24.**

### Correcting the baseline

Phase 0 said everything Lumence replaces "costs nothing to reach". **That was wrong**, and Adil
corrected it. What today actually costs:

| Job | Today |
|---|---|
| Jot a thought | ~0 — the document is already open |
| Write the day's plan | ~0 — same document |
| Start a focus timer | Browser → find or open the Google tab → type → enter |
| Refine writing | Copy → switch tab → paste → read → copy → switch back → paste |
| See where the day went | **Impossible.** Nothing records it |

**Lumence starts behind on the notepad only, and ahead on everything else.** The fragmentation
*is* the cost — which is the premise of `01-problem.md`. The notepad is the single surface where
Lumence can lose.

### The three jobs as flows

**Job 1 — write the day's plan**
`open Lumence → todos panel → type` — typing *is* creating. No dialog, no save button.

**Job 2 — capture a thought mid-work**
`alt-tab → cursor already in the notepad → type` — two steps, one of which belongs to the
operating system. **This is the flow that must not grow.**

**Job 3 — commit to a focus block, then check it**
`start: timer page → type duration → enter`
`later: day view → pick the day → see the lock-in against where attention actually went`
The two halves are hours apart, which is why they live on different screens.

### Supporting flows

- **Refine writing:** `notepad → copy → chat screen → paste → read → copy → back → paste`.
  Still copy-paste by design (spec M, *Notes*); the win is that both ends are in one app.
- **Post on X:** `notepad → copy → button → X opens in a new tab`.
- **Set up tracking:** `register a device → token shown once → paste into the daemon's config`.
  A one-time flow that had never been designed. Iteration 2 needs it.
- **Auth:** `sign up → verification email → link → signed in`; `forgot password → email → link →
  new password`.

### Decisions — main screen

**The notepad owns the screen.** Three things side by side was rejected as clutter. The notepad
is full width by default, which also settles where the cursor goes: there is nowhere else for it
to be.

**Todos slide in from the left on a keyboard shortcut**, taking about a quarter of the width; the
notepad reflows. Not permanently on screen.
- **It remembers its last state.** Open stays open, closed stays closed.
- **It never force-opens** — not in the morning, not when today is empty. Rejected deliberately:
  a panel that appears on its own is a panel that appears when you did not want it.

**The shortcut must be a modifier combination.** The cursor lives in the notepad, so any bare key
is text. No single-letter shortcuts are possible anywhere on this screen.

**A shortcut-only panel is invisible to anyone who does not know it exists.** Accepted — there is
one persona and he will know. Screen 6 documents them.

### Decisions — timer

**Setting up and starting a lock-in lives on its own page**, not on main. This is parity with
today, where the Google timer is a separate tab.

**While a lock-in runs, a small countdown readout sits in the corner of the main screen.** Just
the number. A timer you cannot see is a timer you forget, and the readout costs almost no space.

**It beeps at 00:00:00**, as the Google timer does.
> **Scope change.** `02-spec.md` section L lists *"notifications when a session ends"* under
> **Out**. Adil put the beep back in on 2026-10-24: it is Google-timer parity and the timer was
> specified to behave exactly like the Google timer (ADR 0006). Small, and recorded rather than
> slid in.

### Decisions — shortcuts

**Fixed in v1. Not customisable.**
- A reference screen lists them. Nothing is stored per user.
- **Customisation was considered and deferred:** it needs a settings table, an editing screen and
  conflict detection, and `04-contracts.md` §1.8 states there is no settings table and nothing is
  configurable per user. [ADR 0006](adr/0006-lock-in-is-a-plain-countdown.md) avoided a settings
  area on purpose.
- **Additive later** — the table can arrive without disturbing anything decided here.

### Decisions

**The cursor does not move when the panel opens.** It stays in the notepad. The shortcut shows
the panel; it does not hand over focus. Rejected: jumping to "new todo", which would make the
shortcut double as "add a todo" at the cost of losing your place mid-sentence.

**Status is a circle you click to cycle.** `○` pending → `◐` in progress → `●` completed → back
round. Three states, so cycling is predictable and there is no dropdown.

**Typing in the box is creating.** No save button, no dialog.

**Delayed is shown as an age marker, not a style change.**
`○ write the ADR    3d`
- **Grey was chosen and then reversed.** The problem with grey: it makes things fade, and in most
  interfaces grey means *done* or *switched off*. The one todo you still owe would have been the
  one your eye skips.
- **The marker reports instead of styling.** It says how long it has been and judges nothing,
  which is [ADR 0006](adr/0006-lock-in-is-a-plain-countdown.md)'s stance applied to a todo.
- It also carries information grey never did — three days late and thirty look different.
- **Also rejected:** a different circle glyph (one more symbol to learn); grouping delayed todos
  under an "EARLIER" heading (structurally the cleanest, and it would have fixed the TODAY header
  being quietly wrong, but Adil preferred the marker).
- `delayed` is derived, never stored ([ADR 0018](adr/0018-delayed-is-derived-not-stored.md)), so
  this is a rendering rule and nothing more.

**The circle explains itself on hover.** A tooltip names the current state and what a click will
do — *"In progress → Done"*.
- Rejected: a permanent legend in the panel. Always visible and nothing to discover, but it
  spends two lines of panel height forever teaching a lesson learned in one sitting.
- Hover-only is fine here: one persona, desktop, no touch.

### Day view

The screen where the product's value lands — the "check" half of job 3.

```
┌──────────────────────────────────────────────────────────────┐
│  Lumence  ⬤ ⬤ ⬤ ⬤                            01:23:45       │
├──────────────────────────────────────────────────────────────┤
│   ◀   Fri 24 Oct   ▶   ·   6h 20m            [Day] [Lock-ins]│
│                        ▲                                     │
│                        └─ the day's total                    │
│   06   08   10   12   14   16   18   20   22                 │
│   ├────┼────┼────┼────┼────┼────┼────┼────┼────┤             │
│          ▓▓▓▓▓▓▓▓        ▓▓▓▓▓▓▓▓▓▓▓▓                        │
│          2h lock-in      3h lock-in                          │
│                                                              │
├───────────────────────────────┬──────────────────────────────┤
│  APPLICATIONS                 │  WEBSITES                    │
│                               │                              │
│  Code            4h 12m  ████ │  github.com     1h 05m  ████ │
│  Chrome          1h 24m  █▌   │  localhost      0h 48m  ███  │
│  Slack           0h 40m  █    │  claude.ai      0h 22m  █    │
│  Terminal        0h 18m  ▌    │  news.yc        0h 15m  ▌    │
│  Desktop         0h 06m  ▌    │                              │
│                               │                              │
└───────────────────────────────┴──────────────────────────────┘
```

#### The total, and what "away time" means here

**The day shows a total: `6h 20m`, beside the date.**

Adil settled a confusion the AI had introduced. **If you were away for four hours, you worked
six. Six is the total.** The four hours are not missing from anything — they are simply never
mentioned, anywhere in the app. Nothing on this screen compares your six hours to a ten-hour day
or to anything else, so there is no gap to hide.

The AI had argued against showing a total at all, on the grounds that it would read as a
shortfall. That reasoning was wrong, and is recorded here rather than quietly dropped: it only
holds if something on screen states how long the day *could* have been, and nothing does.

**Placement: beside the date.** It is the headline number for the day and the first thing you
look for. Rejected: under the application list like a receipt total — correct arithmetic, but it
buries the number you came for.

**Bars are scaled to the largest row**, so the top bar is full and the rest are drawn against it.
This is a presentation choice, not a correctness one — it simply compares applications to each
other, which is the only comparison this screen is for.

#### Other decisions

**The timeline shows lock-ins only**, not activity. This is spec D4 exactly: sessions positioned
on the day so intention can be compared against where attention went.
- **Considered and rejected for v1:** a band under each lock-in showing which application held
  focus through it. Far more useful for "did my claim hold" — you would *see* the drift rather
  than infer it — but it is more than D4 asks for and it is the largest build on this screen.
  Additive later; nothing here blocks it.

**The lock-in review (spec L7) is a tab on this screen**, not a separate page.
- You come to the day view to compare intention against attention. A drill-in takes you off the
  day and you have to navigate back; a tab keeps both one click apart.
- The review itself is the same aggregation as the day, bounded by the session window instead of
  the day — same rules, including idle.

**Empty state (spec D3): "No activity recorded."** Nothing else.
- Not an error. It is the normal state of every day before the daemon was installed.
- **Not "today"** — the day picker pages back, so "today" would be wrong on older days.

**No colour, no categories, no score** ([ADR 0006](adr/0006-lock-in-is-a-plain-countdown.md)).

### Timer

Job 3's "commit" half. Google-timer parity: type a number, press start.

**Nothing running:**
```
┌──────────────────────────────────────────────────────────────┐
│  Lumence  ⬤ ⬤ ⬤ ⬤                                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                      ┌──────────────┐                        │
│                      │  ▌ 00:00:00  │   ← cursor lands here  │
│                      └──────────────┘                        │
│                                                              │
│                        ┌─────────┐                           │
│                        │  Start  │                           │
│                        └─────────┘                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**Running:**
```
┌──────────────────────────────────────────────────────────────┐
│  Lumence  ⬤ ⬤ ⬤ ⬤                                           │
├──────────────────────────────────────────────────────────────┤
│                                                         🏁   │
│   ───────────────────🏃──────────────────────────────────┤   │
│   start                                              finish  │
│                                                              │
│                       01:23:45                               │
│                                                              │
│                 ┌───────┐    ┌───────┐                       │
│                 │ Pause │    │ Reset │                       │
│                 └───────┘    └───────┘                       │
└──────────────────────────────────────────────────────────────┘
```

**Paused** — the number is frozen, `Pause` reads `Resume`, and the runner stops and catches
their breath.

#### Decisions

**Nothing else lives on this screen.** Type a number, press start — the benchmark ADR 0006 set.
The cursor lands in the field on load, as it does in the notepad.

**No "end early" button**, per [ADR 0006](adr/0006-lock-in-is-a-plain-countdown.md). The only
exits are reaching zero and resetting.

**Reset does not ask for confirmation.** Spec L5 discards the lock-in entirely, so a mis-click at
1h58m loses two hours with no way back. **The AI proposed confirming only on long-running
lock-ins and was overruled** — Adil wants Google-timer parity, which has no confirmation. The
loss is real and accepted.

**The countdown does not appear in the header on this screen.** It is already the largest thing
on the page; repeating it in the header is redundancy. The header readout exists for *other*
screens, so you can see a running lock-in while working elsewhere.

#### The progress display — a runner on a path

A left-to-right journey rather than a ring. Position is the information: you read how far you
have come without decoding an angle.

**A depleting indicator is legitimate here and would not be on the day view.** The lock-in has a
target — you chose the duration. The day has none. Progress toward a goal you set is not the
product judging you.

**Chosen (Adil, 2026-10-24):**
- **A runner travelling the path**, with a finish line at the right.
- **No checkpoints or milestone markers** along the way. The path is unbroken.
- **Arrival is celebrated** — the runner crosses the line, confetti or similar fires, and the
  beep sounds. This is the payoff moment and is worth making the best part of the screen.
- **On pause the runner stops and catches their breath**; resuming starts them again. Charming
  rather than scolding — nothing nags while paused.

**The AI argued against the character and was overruled.** Recorded so the reasoning survives
rather than being re-argued: an animated figure sits in peripheral vision for hours in a product
about protecting attention; a runner that reacts to a pause is the product having an opinion
about your break; and gamification is on the non-goals list. **Adil's answer, which stands:** it
is his product and his daily tool, and enjoying it is a real requirement, not a weakness. A tool
he finds boring is a tool he stops opening — which is success criterion 7.

**Craft notes, so it stays pleasant over a three-hour lock-in:**
- **Keep the run cycle slow and loose.** Twitchy animation becomes irritating by minute forty.
- **Keep the character small** relative to the number. You glance for the time; the runner is the
  pleasure, not the reading.
- **Honour `prefers-reduced-motion`** — one line of CSS, and it stops the animation fighting the
  browser's own accessibility setting.

#### Considered and not taken
- **A ring** (Google's). Read instantly by everyone, and completely conventional.
- **An arc** — lighter, slightly harder to judge at a glance.
- **A square with a depleting border** — distinctive, but corners break the sense of smooth
  depletion and it reads worst of the four.
- **Milestone markers** at 25/50/75% — would give a long lock-in several small moments instead of
  one. Cut deliberately: Adil wanted the path unbroken.
- **Scenery that scrolls** — a sun crossing the sky, a moving background. Not taken for v1.
- **A path whose length reflects the duration** — a 25-minute track versus a 3-hour trail. Not
  taken for v1.

#### Decisions

**The empty state says the chat is not saved.**
`"Nothing here is saved. Copy anything you want to keep."`
- Spec M4 clears the conversation when the browser closes — and this screen looks exactly like
  every chat application where that would be a bug. Without the line, the first few times will
  feel like data loss.
- It sits in the empty state, so it is read on arrival and invisible once a conversation starts.
- Rejected: saying nothing. Defensible with one persona, but a sentence is cheaper than the
  surprise.

**The remaining turns sit top-centre.** `12 of 20 left`.
- Rejected: top-right, which is where such counters usually go and which is easy not to look at.
- Rejected: beside **Send**, which is where you commit — harder to ignore at turn 19, but it
  crowds the action.
- Centre is the compromise Adil chose: present without being attached to the button.

**A copy button on every reply** (spec M3). Copy-paste between the notepad and the chat is the
user's job in both directions, deliberately (spec M, *Notes*) — so the copy affordance has to be
obvious.

#### Failure and the cap

**A failed reply (M6, E4):**
```
│          ┌────────────────────────────────────────────────┐  │
│   reply  │ Something went wrong. Nothing was sent.        │  │
│          │                                     ↻ retry    │  │
│          └────────────────────────────────────────────────┘  │
```
- **No half-written reply is ever left on screen.** Either a whole reply arrives, or this does.
- **The turn is not counted.** Failures are free and retryable — the counter only moves on
  success (`03-domain.md` invariant 15a).

**The cap reached (M5, E12):**
```
│  ┌────────────────────────────────────────────┐  ┌────────┐  │
│  │ 20 of 20 used. Resets tomorrow.            │  │  Send  │  │
│  └────────────────────────────────────────────┘  └────────┘  │
│                                                   (disabled) │
```
- Stated plainly in the input itself, where you were about to type.
- The cap is a cost control, not a plan tier ([ADR 0010](adr/0010-llm-provider-openai-behind-an-adapter.md)),
  so the message says when it resets and offers nothing to upgrade.
